## Design Specificity Verdict

Explicitly authored for this product, with two leaks toward the generic.

The instrument-grade character lives in the _code_, not the prose: mono-readout stays enforced at the site of reading, families run on disciplined `base`/`strong` semantics, shadow-paints-itself is genuinely implemented, the One Contact Rule holds everywhere, and under/over glass is demonstrated in `MaterialScene`. A SaaS dashboard could not ship this unchanged.

The leaks: the "dismantled and retired" six-role matrix still lives in `tokens/colors.stylex.ts` and paints 18–55% radial washes over every page via `Stage`/`ShellWrapper`; `colors.primary` is literally identical to `families.aurora` and `colors.ring`. The room is brighter than the copy implies.

**Deterministic scan:** `impeccable detect` returned 1 advisory — `tokens/shadows.stylex.ts:10` `oklch(0% 0 0)`, undocumented in the DESIGN.md palette sidecar (true positive, low severity: a shadow base variable, not a consumer color). Manual scan added: Toggle, Checkbox, Segmented, RadioGroup all lack the `pressable` intent; touch targets all sit below 44px. Token compliance otherwise near-perfect — one false positive: `ColorField.tsx:23` `#000000`, a legitimate picker fallback.

## Overall Impression

A genuinely authored, instrument-grade toolkit whose internal documentation is a model of clarity — undercut in three places where the code contradicts its own contract: the Pilot Light glow never renders, glass sits on in-flow docked panels, and a "retired" semantic matrix still colors the room. The biggest opportunity: make the code deliver the two signature moments DESIGN.md promises — the glowing living thing when a control arms, and the dim room where the canvas is the only light.

## What's Working

1. **The token/anatomy architecture is real, not aspirational.** `base`/`strong` family tensions, `shadowColor`-derived shadows, orthogonal glow/elevation/glass effects, One Contact Rule — all shared mechanisms; zero raw palette references in any component.
2. **The Slider is the flagship component.** Self-tinted recessed rail, strong-seeded thumb whose cast agrees with its hue, mono output, container keyboard ring — the language executed at instrument grade.
3. **Documentation quality.** DESIGN.md and component-authoring.md record every derivation with its rationale (contrast pull directions, why `sunken` uses a top-light line, why glass deepened to 45%).

## Priority Issues

### [P0] P0-A — Amber-on-cream selection text is unreadable in light mode

`Segmented.tsx` and `RadioGroup.tsx` paint the chosen option with `amberBase` + `colors.background` — ~1.1:1 contrast. The fix already ships in the tree: `families.amber.ink.fg`, defined precisely for "text painting on its tint."

- **Fix:** chosen-option color derives from `fam.ink` (or forced neutral for amber in light).
- **Suggested command:** `$impeccable audit`

### [P1] P1-B — The Pilot Light glow never renders

In Toggle/Checkbox, `glow.glowRing` and `focusRing.base` compile to the same runtime `box-shadow` key; styleq dedupes to whichever registers last, so the 6px same-hue halo is dropped — "on" is a flat fill. Button has the mirror issue where `pressable.base` wins and `focusRing.base` is dead code.

- **Fix:** order glow after the focus ring, or fold the ring into glow's shadow list as pressable did.
- **Suggested command:** `$impeccable polish`

### [P1] P1-C — Glass is applied to in-flow panels and the room glows at 55% on load

`ExperimentShell.tsx` applies `glass.glass` unconditionally, including the docked (non-floating) placement, so docked text contrast depends on ShellWrapper's saturated backdrop — a direct Glass-on-Floating-Only violation. The 45–55% radial washes in `Stage`/`ShellWrapper` are the loudest elements before any control is touched.

- **Fix:** apply glass only when `isFloating`; source ambient washes onto light-field regime at far lower presence.
- **Suggested command:** `$impeccable distill` / `$impeccable quieter`
- **Open decision:** whether the ShellWrapper ambience is intended (see work-orders S6).

### [P2] P2-D — The retired six-role matrix is still exported and decorating

`primary/secondary/accent/destructive/warning` remain in `colors.stylex.ts`; `primary` is an exact alias of `aurora`/`ring`; `SectionHeading` hardcodes `colors.accent`; `Swatch` teaches consumers the legacy roles as canonical.

- **Fix:** alias `primary` → `families.aurora`/`ring`, re-source SectionHeading and Stage/Shell washes, make Swatch demonstrate families.
- **Suggested command:** `$impeccable extract`

### [P2] P2-E — Touch targets never reach 44×44 and pressable feedback is missing on half the widgets

Hit areas: Button ~33px, Toggle 20px, Checkbox 18px, Radio 28px, Segmented ~19px, Slider rail 14px. Toggle/Checkbox/Segmented/RadioGroup also lack `pressable` (no hover shadow, no active press).

- **Fix:** `touchTarget` const + padded hit-area/min-height; add `pressable.base` to the four widgets.
- **Suggested command:** `$impeccable adapt`

## Persona Red Flags

**Alex (Power User)** — Density + mono-readout scanning is a real win. But: three competing heading recipes slow pattern-matching; `primary≡aurora≡ring` makes the token API ambiguous; no reset-to-default gesture, so returning to a known baseline is manual re-entry; 14px slider rail is a keyboard-first annoyance for someone expecting instrument precision.

**Jordan (First-Timer)** — No first-run/empty-state pattern anywhere. A fresh scene opens as a wall of uppercase mono labels (`CUTOFF`, `RESONANCE`) and identity LEDs before any reward. ShellWrapper's vivid backdrop can read as broken/glitchy rather than ambient; the icon-only "hide panel" button may be mistaken for canvas content.

**Sam (Accessibility)** — The P0 amber-on-cream (~1.1:1) is the headline failure. Touch targets all sub-44px. Dark-mode `faded*` fills on toggle/checkbox marks are documented at ~2–2.7:1 shortfalls. Credit: `prefers-reduced-motion` honored everywhere, roving-tabindex arrows + Home/End on RadioGroup/Segmented, `aria-live` on live values, semantic elements throughout.

## Minor Observations

- Button's `focusRing.base` is provably dead code — droppable.
- `Led` accepts arbitrary color strings with no guard — that's how `colors.accent` sneaks into SectionHeading; consider a `FamilyName`-typed `Led`.
- `ColorField` has no family/LED row while every other field surfaces one.
- Raw pixel geometry scattered in components (34/20/14/18px, 1px pads) despite the const-layer policy.
- The `family` prop on Segmented/RadioGroup colors _selection_ in a family hue — identity-less groups per contract should take the contact hue.
- Card's `glass` variant works only because of argument ordering — fragile to refactors.
- The `sunken` shadow's top-light line is a genuinely better recess idiom.

**Cognitive load:** 2 hard failures (visual hierarchy — three heading recipes; progressive disclosure — panel toggle is the only reveal mechanism) + 2 partials (working memory via broken glow; color-state signal). **Emotional journey:** 6/10 — the instrument feel lands, then stalls at activation (glow) and entrée (ambience + no first-run).

## Questions to Consider

1. If the Pilot Light (glow) is the system's warm signal and it doesn't render, what else is asserted but untested? Does the visual laboratory exercise compiled StyleX output, and would a visual-regression golden have caught this?
2. The matrix was "retired" yet still exports and paints every page background. Was the six-role system replaced by light fields, or just rebranded?
3. Three heading components, three recipes, all uppercase, all muted — is hierarchy real or lexical?
4. Amber's ink token exists to solve amber-on-tint text, and the only two components that paint text on tint don't consume it. What does that say about the review loop?
5. "A glowing thing is a living thing" — but the ambient shell glows at 55% before anything is touched. Is that under-light, or is the room switched on at all times?
