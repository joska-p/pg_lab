# Architecture

Document de travail. Les termes sont définis dans `glossary.md`.

Plateforme : TypeScript, React, Zustand, **WebGL2** (GLSL ES 3.00). Un petit module `shared` fournit les utilitaires sans domaine (par exemple le type `Brand`).

## Principe directeur

Chaque module a **une responsabilité** et ne connaît que les modules situés en dessous de lui.
Le cœur (catalogue, expression, grammaire, générateur, compilateur) est du TypeScript pur : **ni React, ni DOM, ni GPU**. Seul le renderer touche à WebGL.

```
UI (React + Zustand)
   │
   ├── Renderer ───────── Compilateur GLSL ──┐
   │                                          │
   ├── Persistance (œuvre, export)            │
   │                                          ▼
   └── Générateur ── Grammaire ──► Expression
                                       │
                                  Catalogue (opérateurs + dépendances)
```

Le renderer n'importe du compilateur que le **type** `CompiledShader` (dépendance de type uniquement).

Chaîne de production d'une image :

```
grammaire + seed → expression → compilateur (GLSL) → renderer (texture) → [post-traitement, plus tard] → écran
```

## Modules

| Module            | Responsabilité (une phrase)                                                                                                     | Entrées → sorties                      | Ne sait rien de     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ------------------- |
| **catalog**       | Déclarer les opérateurs et les dépendances shader, et les retrouver                                                             | — → définitions                        | tout le reste       |
| **expression**    | Représenter, valider et sérialiser une expression                                                                               | — → trois arbres immuables             | grammaires, GPU, UI |
| **random**        | Fournir un générateur pseudo-aléatoire déterministe                                                                             | seed → flux de nombres                 | tout le reste       |
| **grammar**       | Décrire un espace d'expressions, vérifier qu'il est valide et le faire varier                                                   | données ou grammaire + rng → grammaire | rendu, UI           |
| **generator**     | Produire une expression à partir d'une grammaire et d'une seed                                                                  | grammaire + seed → expression          | rendu, UI           |
| **compiler**      | Transformer une expression en shader : résoudre le préambule, gérer les contextes de coordonnées, partager les sous-expressions | expression → source GLSL               | UI, persistance     |
| **renderer**      | Exécuter le shader sur un canvas, gérer résolution et phase, puis la passe finale                                               | GLSL + résolution + phase → pixels     | génération          |
| **artwork**       | Définir le format d'œuvre et son import/export                                                                                  | œuvre ↔ JSON                           | rendu               |
| **explorer (UI)** | Orchestrer : galerie, inspection, historique                                                                                    | actions utilisateur → états            | internals du cœur   |

Règle pratique : si une fonction est difficile à nommer, elle fait trop de choses. On la découpe.

## Le catalogue

C'est la pièce la plus importante pour garder le code propre. Un opérateur est **une donnée déclarative**, pas du code éparpillé dans plusieurs `switch`. Le détail est dans `catalog-spec.md`.

Le catalogue est un **registre statique** de specs (un fichier par famille : `operators/terminals.ts`, `arithmetic.ts`…), que `createDefaultCatalog` instancie en `Operator`. `Catalog` retrouve un opérateur par son nom, expose les listes (`operators`, `terminals`, `dependencies`) et calcule la fermeture des dépendances. Les multiplicités sont mesurées **une fois**, à la construction de l'`Operator` (D29, D42).

Deux capacités optionnelles, **indépendantes**, que n'importe quel opérateur peut déclarer :

- **`requires`** : des dépendances (fonctions GLSL auxiliaires, uniforms). Le compilateur en déduit le préambule.
- **entrées `inner` + `coords`** : ces entrées sont évaluées dans un nouveau contexte de coordonnées, calculé par `coords` à partir des entrées `inputs`. C'est ce qui permet les transformateurs (déformation, rotation, zoom).

Il n'y a **pas** de champ `kind` ni de `switch` sur des types d'opérateurs : le compilateur lit ces capacités, sans connaître chaque opérateur.

## Le compilateur

Il fait trois choses :

1. **Préambule** : collecte les dépendances des opérateurs utilisés, ajoute les dépendances de ces dépendances, supprime les doublons, trie dans l'ordre. Écrit le résultat une seule fois.
2. **Contextes de coordonnées** : un opérateur à entrée `inner` crée une nouvelle variable de coordonnées ; ses entrées `inner` sont compilées avec celle-ci.
3. **Partage de sous-expressions** : une sous-expression n'est partagée que si elle apparaît **dans le même contexte**. `sin(x)` dans deux contextes différents n'est pas le même sommet. La clé de partage est donc (contexte, opérateur, paramètres, entrées). Le nombre d'usages d'un sommet tient compte de la **multiplicité** des entrées dans le GLSL des opérateurs (D29), sans quoi `sqr` ou `mix` feraient exploser le texte.

Le partage n'est pas toujours favorable (pression sur les registres) ; on le mesurera avant de l'optimiser davantage.

## Temps et animation

- Une expression est une fonction de `(x, y, t)`. Le temps entre par des **terminaux** (`tsin`, `tcos`) qui lisent l'uniform `u_phase`.
- La phase boucle sur `[0, 1)` : l'animation boucle parfaitement, ce qui facilite l'export en GIF ou en vidéo.
- Il n'y a pas de « mode animation » : c'est le vocabulaire qui décide. Sans terminaux de temps (poids à 0), l'image est statique.
- La fluidité dépend aussi des autres opérateurs : `gt` et `select` créent des bascules brutales, et des `sin`/`mul` imbriqués accélèrent le mouvement. C'est une propriété de la grammaire, donc réglable par les poids.

## Post-traitement

C'est une étape du **renderer**, pas du catalogue ni du générateur. Le renderer dessine d'abord l'expression dans une texture, puis une passe finale la copie à l'écran. Les effets (flou, grain, correction de couleur) viendront dans cette passe, plus tard, sans rien changer en amont.

## Tests (sans évaluateur CPU)

- **Compilateur** : instantanés du GLSL produit pour une grammaire et une seed données (déterministe, sans GPU).
- **Catalogue** : définitions valides, clés conformes, dépendances résolues, pas de cycle, `inner` ⇔ `coords`, chaque entrée utilisée, multiplicité indépendante des paramètres.
- **Générateur** : expressions toujours valides pour les grammaires valides, profondeur et nombre de nœuds respectés.
- **Plage** (navigateur, **requis**, exécuté en CI dans un Chromium headless) : un shader de test écrit un indicateur de violation (hors `[-1, 1]` à `1e-6` près, ou non fini) pour chaque opérateur, y compris sous `ra_fold2`.
- **Fuzzing** (navigateur, requis) : mille expressions générées, compilées avec chaque politique, acceptées par le pilote.

| D22 | Le partage se fait par **hash-consing** : la clé d'une valeur est (contexte, opérateur, paramètres, identifiants des entrées), et les contextes sont eux aussi internés. Le partage agit **entre les trois canaux**.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D23 | Politique de partage réglable (`none`, `shared`, `all`), `shared` par défaut. | D24 | Le compilateur parenthèse tout texte en ligne qui n'est pas un atome, et écrit les littéraux de façon sûre (`-(-0.3)` et non `--0.3`). | D25 | L'**image** (`RenderSize`) est indépendante de l'**affichage** (canvas). `[-1, 1]²` est toujours étiré sur toute l'image ; le placement (`stretch` ou `contain`) se fait dans la passe finale.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| D26 | Orientation : `y` vers le haut. Les valeurs `[0, 1]` sont écrites telles quelles en RGBA8 et lues comme du sRGB, sans conversion linéaire.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D27 | Un échec de compilation ou de liaison du shader n'est **pas une exception** : `setShader` renvoie le résultat et conserve le programme précédent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D28 | Le renderer ne tient pas de boucle d'animation (c'est l'UI) et sait se reconstruire après une perte de contexte à partir du dernier `CompiledShader`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D29 | La **multiplicité** de chaque entrée est mesurée en sondant `glsl` et `coords` avec des sentinelles (paramètres au minimum). Le **catalogue** le fait une fois, à la construction de l'`Operator` ; le compilateur compte les usages à partir de ces valeurs. Un opérateur peut donc réutiliser une entrée sans risque d'explosion du texte.                                                                                                                                                                                                                                                                                                                          |
| D30 | Conventions de noms : uniforms `u_*`, fonctions auxiliaires GLSL `ra_*`, opérateurs `^[a-z][a-z0-9_]*$`. Aucune collision possible avec `v<n>`, `c<n>`, `v_p`, `o_color`, `main`, `PI` ni avec les mots du GLSL.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D31 | Contrat de plage **à quelques ULP près** (tolérance `1e-6`). Le `clamp` final est le filet. Les tests de plage et de fuzzing en navigateur sont **requis**, pas facultatifs, puisqu'il n'y a pas d'évaluateur CPU (D9).                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D32 | `minDepth` est conservé tel que défini en D18 (aucune feuille avant cette profondeur). Le coût est connu et documenté (taille minimale, §5 de la spec grammaire). Pas de variante « au moins un chemin atteint minDepth ».                                                                                                                                                                                                                                                                                                                                                                                                                                            |

Un poids vivant est arrondi à 3 décimales et minoré à `0.001` ; il ne peut donc pas disparaître par arrondi. Les randomisations parcourent les noms dans l'ordre alphabétique.                                                                                                                                                                                                                                                                                                                                                                                                 |

La réduction de résolution pendant l'animation est l'affaire de l'UI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D37 | Grammaires : export et import individuels (fichier versionné) en v1. Liste sauvegardée, comparaison et clé canonique de grammaire en v2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D38 | Vocabulaire : _sommet_ (compilateur) ≠ _valeur_ (nombre dans `[-1, 1]`) ≠ _nœud_ (arbre d'expression).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| D39 | Une grammaire permet les images unies (pas de règle « au moins une coordonnée »). La randomisation protège `x` et `y` par défaut (`DEFAULT_KEEP`). | D40 | Le vocabulaire est l'ensemble des opérateurs de poids > 0. L'UI présente la liste complète du catalogue : un opérateur entre/sort par son poids, jamais par une clé qui apparaît ou disparaît.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| D42 | Le catalogue est un **registre statique** de specs (clé = nom de l'opérateur). La forme tient aux **types** et à des **tests** ; le runtime ne garde que `inner` ⇔ `coords` et « entrée utilisée ».                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
