## Design Specificity Verdict

Explicitly authored for this product, with two leaks toward the generic.

The instrument-grade character lives in the code, not the prose: the mono-readout rule is enforced at the site of reading, families are consumed with disciplined `base`/`strong` semantics, shadow-paints-itself is genuinely implemented, the One Contact Rule holds everywhere, and glass/under-light depths are demonstrated in `MaterialScene`. A SaaS dashboard could not ship this unchanged.

The two leaks: (1) the "dismantled and retired" six-role matrix still lives in `tokens/colors.stylex.ts` and paints 18–55% radial washes over every page background via `Stage`/`ShellWrapper`, and `Swatch.tsx` still teaches consumers the legacy roles; (2) `colors.primary` is literally identical to `families.aurora` and `colors.ring` — two redundant vocabularies for one hue. The room is brighter than the copy implies.

**Deterministic scan:** `impeccable detect` returned 1 advisory finding — `tokens/shadows.stylex.ts:10` uses `oklch(0% 0 0)`, not documented in the DESIGN.md palette sidecar. True positive, low severity: it is the shadow base variable rather than a consumer-visible color. Manual code scan added: Toggle, Checkbox, Segmented, and RadioGroup all lack the `pressable` intent (no hover shadow, no active press) — corroborated by the design review (Button is the only true pressable); and touch targets all sit below 44px — corroborated by review P2-5. Outside that, token compliance is near-perfect: only one false positive, `ColorField.tsx:23` `#000000`, a legitimate color-picker fallback.

**Visual overlays:** Not applicable. The target is a component library with no standalone runnable surface; `apps/dev` is a separate target. No injection was attempted and no user-visible overlay exists.

## Overall Impression

A genuinely authored, instrument-grade toolkit whose internal documentation is a model of clarity — undercut in three places where the code contradicts its own contract: the Pilot Light glow never renders, glass sits on in-flow docked panels, and a "retired" semantic matrix still colors the room. The single biggest opportunity: make the code deliver the two signature moments DESIGN.md promises — the glowing living thing when a control arms, and the dim room where the canvas is the only light.

## What's Working

1. **The token/anatomy architecture is real, not aspirational.** `base`/`strong` family tensions, `shadowColor`-derived shadows, orthogonal glow/elevation/glass effects, and the One Contact Rule are shared mechanisms across every widget — and grep confirms zero raw palette references in components.
2. **The Slider is the flagship component.** Self-tinted recessed rail, strong-seeded neutral thumb whose cast agrees with its hue, mono output, keyboard ring on the container — the language executed at instrument grade.
3. **Documentation quality.** DESIGN.md and component-authoring.md record every derivation with its rationale (contrast pull directions, why `sunken` uses a top-light line, why glass deepened to 45%): rare and valuable at any toolkit size.

## Priority Issues

**[P0] Amber-on-cream selection text is unreadable in light mode.** `Segmented.tsx` and `RadioGroup.tsx` paint the chosen option with `amberBase` and `color: colors.background` — in light mode that's ~1.1:1 contrast, and the toolkit already ships the fix: `families.amber.ink.fg` was defined precisely for "text painting on its tint."

- **Why it matters:** This is the one text-on-tint case in the whole system and the ink token exists to solve it; as shipped it fails WCAG by an order of magnitude in light mode.
- **Fix:** Chosen-option color derives from `fam.ink` (or forced neutral for amber in light).
- **Command:** `$impeccable audit`

**[P1] The Pilot Light glow never renders.** In Toggle and Checkbox, `glow.glowRing` compiles to the same runtime `box-shadow` key as `focusRing.base`; styleq dedupes to whichever registers last, so the 6px same-hue halo is dropped — "on" renders as a flat fill. The system's signature state affordance is dead in the merged output; Button has the mirror problem where `pressable.base` silently wins and `focusRing.base` is dead code.

- **Why it matters:** A glowing thing is a living thing is the contract's own language. Without the halo, live vs off falls back to an opacity delta, and heuristic #1 erodes.
- **Fix:** Order glow after the focus ring (or fold the ring into glow's shadow list as pressable did) so the halo survives dedup.
- **Command:** `$impeccable polish`

**[P1] Glass is applied to in-flow panels and the room glows at 55% on load.** `ExperimentShell.tsx` unconditionally applies `glass.glass`, including the docked (non-floating) placement, so in-flow text contrast depends on ShellWrapper's saturated backdrop — a direct violation of the Glass-on-Floating-Only Rule. Separately, the 45–55% radial washes in `Stage`/`ShellWrapper` are the loudest elements on screen before any control is touched.

- **Why it matters:** Canvas-first is the product's reason to exist; the scaffold currently competes with the canvas.
- **Fix:** Apply glass only when `isFloating`; source ambient washes onto families/light-field regime at much lower presence (or drop for the default shell).
- **Command:** `$impeccable distill` / `$impeccable quieter`

**[P2] The retired six-role matrix is still exported and decorating.** `primary/secondary/accent/destructive/warning` remain in `colors.stylex.ts`; `primary` is an exact alias of `aurora`/`ring`; `SectionHeading` hardcodes `colors.accent`; `Swatch` teaches consumers the legacy roles as canonical.

- **Why it matters:** Two vocabularies for one hue make the token API ambiguous ("which is canonical?") and undo the contract's "matrix dismantled and retired" commitment.
- **Fix:** Alias `primary` to `families.aurora`/`ring`, re-source SectionHeading's LED and Stage/Shell washes onto families, and make Swatch demonstrate families.
- **Command:** `$impeccable extract` / `$impeccable distill`

**[P2] Touch targets never reach 44×44 and pressable feedback is missing on half the widgets.** Hit areas: Button ~33px, Toggle 20px, Checkbox 18px, Radio 28px, Segmented ~19px, Slider rail 14px. Toggle/Checkbox/Segmented/RadioGroup also lack the `pressable` intent, so they get no hover shadow or active press.

- **Why it matters:** Touch-first is a hard requirement; thumb targets at 18–20px are the classic accidental-misclick zone, and the tactile language dies where the atelier's "answer when touched" promise applies most.
- **Fix:** A `touchTarget` const + padded hit-area/min-height treatment; add `pressable.base` to the four widgets.
- **Command:** `$impeccable adapt`

## Persona Red Flags

**Alex (Power User / collaborating developer)** — Density and mono-readout scanning are a genuine win for rapid setup. But: three competing heading recipes slow pattern-matching across apps; the `primary≡aurora≡ring` duplication makes the token API ambiguous; there is no reset-to-default gesture in any field, so tuning an experiment back to a known baseline requires manual re-entry. The 14px slider rail is a keyboard-first annoyance for someone who expects instrument precision — arrow-key scale hopping or click-to-track-rough + drag-fine would serve them.

**Jordan (First-Timer)** — There is no first-run/empty-state pattern anywhere. A fresh scene opens with a panel of uppercase mono labels (`CUTOFF`, `RESONANCE`) and several identity LEDs before any reward; nothing indicates "the one control to touch first." `ShellWrapper`'s vivid backdrop can read as broken/glitchy rather than ambient to a newcomer, and the icon-only "hide panel" button floating over the canvas may be mistaken for canvas content.

**Sam (Accessibility)** — The P0 amber-on-cream selection text (~1.1:1) is the headline failure. Touch targets are all sub-44px. Dark-mode `faded*` fills on toggle/checkbox marks are documented at ~2–2.7:1 shortfalls — real and on the table. Crediting what works: `prefers-reduced-motion` honored in the spinner and every transition; roving-tabindex arrows + Home/End on RadioGroup/Segmented; `aria-live` on live values; semantic elements throughout; `color-scheme`-driven theming with no flash-of-wrong-mode while keeping direct system-sync.

## Minor Observations

- Button's `focusRing.base` is provably dead code (the later `pressable.base` wins the merge) — droppable.
- `Led` accepts arbitrary color strings with no guard; that is how `colors.accent` sneaks into `SectionHeading`. Consider a `FamilyName`-typed `Led`.
- `ColorField` has no family/LED row while every other field surfaces one — asymmetry in the "field reads a real parameter" promise.
- Raw pixel geometry is scattered in components (34/20/14/18/16/12px, 1px pads) despite the stated policy that geometry belongs in the const layer.
- The `family` prop on Segmented/RadioGroup colors _selection_ in a family hue — adjacent to the prohibited "component variant color"; identity-less groups per the contract should take the contact hue.
- The `sunken` shadow's top-light line is a genuinely better recess idiom than a same-hue inset; the comments explaining it are excellent.
- Card's `glass` variant works only because of argument ordering — fragile to refactors.

## Questions to Consider

1. If the Pilot Light (glow) is the system's warm signal and it doesn't render, what else is asserted but untested? The bug was invisible precisely because the effect layer is so clean that nobody verified merged output. Does the visual laboratory actually exercise compiled StyleX output, and would a visual-regression golden have caught this?
2. The matrix was "retired" yet still exports and paints every page background. Was the six-role system replaced by light fields, or just rebranded? What stops decorative accent fills from returning next month?
3. Three heading components, three recipes, all uppercase, all muted — is hierarchy real or lexical? Would anyone be able to tell the level apart at a glance on a busy panel?
4. Amber's ink token exists to solve amber-on-tint text, and the only two components that paint text on tint don't consume it. What does that say about the review loop that shipped the fix-adjacent token without the fix?
5. "A glowing thing is a living thing" — but the ambient shell glows at 55% before anything is touched. Is that under-light, or is the room switched on at all times?
