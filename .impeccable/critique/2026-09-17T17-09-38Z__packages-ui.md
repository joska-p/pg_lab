### Design Specificity Verdict

**LLM assessment**:
The Terminal Atelier design system achieves exceptional character and identity. Rather than imitating a generic SaaS dashboard with heavy drop shadows, rounded bubble cards, and standard blue focus rings, `@repo/ui` commits fully to a vintage laboratory instrument aesthetic. The Gruvbox color scheme, matte panel surfaces, hairline borders, and "Pilot Light" LED indicators give it a distinct tactile presence that anchors creative tooling.

However, several architectural and layout discrepancies undermine this character:

1. The **Glass-on-Floating-Only Rule** from `DESIGN.md` is broken in `ExperimentShell.tsx`, where `glass.glass` (`backdrop-filter: blur`) is applied unconditionally to in-flow docked panels.
2. In `Button.tsx`, the lack of a `gap` property causes the LED dot to stick directly against button labels, marring the typographic precision.
3. In `ShellWrapper.tsx`, heavy noise and full-viewport gradients violate the "Canvas-first" guideline where chrome must recede behind the creative experiment.

### Overall Impression

`@repo/ui` is a finely crafted, tactile design system with genuine point-of-view and strong accessibility fundamentals (roving tabindex, clamp notices, touch targets). The single biggest opportunity is bringing the component implementations into 100% alignment with the visual contract in `DESIGN.md`—specifically fixing the unconditional glass blur on docked panels, adding proper flex spacing to `Button`, and upgrading `ControlSection` headers to semantic headings.

### What's Working

1. **Tactile Hardware Metaphors**: The concept of "keys", "wells", and "rails" with LED indicator dots (`Led.tsx`) and the Pilot Light press glow (`scale(0.97)` + halo) provides authentic physical feedback without gratuitous animations.
2. **Accessibility-First Controls**: `Segmented` and `RadioGroup` implement full WAI-ARIA roving tabindex and arrow-key navigation; `NumberField` provides friendly inline clamp announcements (`role="alert"`) instead of silently modifying user input.
3. **Touch-First Band Sizing**: `Slider` and `Toggle` enforce a 44px touch band (`touch.hit` / `controlTouchTarget`), ensuring touch screen interaction works smoothly without hover dependency.

### Priority Issues

- **[P1] Violation of "Glass-on-Floating-Only" Rule in ExperimentShell & Card**:
  - _Why it matters_: In `ExperimentShell.tsx`, `glass.glass` is applied to `.panel` regardless of whether `panelPlacement` is `"floating"` or `"docked"`. `DESIGN.md` explicitly dictates: _"Blur and translucency exist only where UI floats above other content. In-flow surfaces stay opaque so text contrast never depends on what sits behind them."_ Docked in-flow panels blur content behind them, degrading text contrast and rendering performance.
  - _Fix_: Apply `glass.glass` only when `isFloating === true`. In `Card.tsx`, ensure `glass` variant is reserved strictly for floating overlays.
  - _Suggested command_: `$impeccable harden packages/ui`

- **[P1] Missing Flex Gap in Button Between LED Mark and Children**:
  - _Why it matters_: `Button.tsx` has `display: "inline-flex"` with `alignItems: "center"` and `justifyContent: "center"`, but lacks `gap: space["2"]`. When a `family` is provided, the `<Led>` mark renders immediately adjacent to `{children}`, causing the LED indicator and label text to collide without margin or whitespace.
  - _Fix_: Add `gap: space["2"]` to `styles.base` in `packages/ui/src/components/Button.tsx`.
  - _Suggested command_: `$impeccable layout packages/ui`

- **[P2] Heading Hierarchy Failure in ControlSection**:
  - _Why it matters_: `ControlSection.tsx` renders section titles as `<span id={titleId} {...stylex.props(heading.level3)}>{title}</span>` inside `<section aria-labelledby={titleId}>`. While the landmark region is accessible, screen reader users navigating by heading keys (`H` or `3`) cannot discover or jump between control sections.
  - _Fix_: Use a semantic `<h3 id={titleId}>` or add `role="heading" aria-level="3"`.
  - _Suggested command_: `$impeccable audit packages/ui`

- **[P2] ColorField Live Region Speech Flooding & Narrow Color Model**:
  - _Why it matters_: In `ColorField.tsx`, `aria-live="polite"` is attached directly to the hex readout span, which updates continuously during color scrubbing and floods screen reader queues. In addition, the component is restricted to hex (`#000000`) while the design system standard is OKLCH.
  - _Fix_: Remove or debounce `aria-live` during active dragging (announce only on commit/blur) and consider supporting wider color gamuts.
  - _Suggested command_: `$impeccable harden packages/ui`

- **[P3] ShellWrapper Noise & Viewport Units Competing with Canvas**:
  - _Why it matters_: `ShellWrapper.tsx` uses `100vw`/`100vh` instead of modern `100dvh`/`100%`, risking scrollbar jumps on desktop and bottom truncation on mobile browsers. Its heavy background noise and dual radial gradients also conflict with the "Canvas-first" principle where outer chrome should stay visually unobtrusive.
  - _Fix_: Use `minHeight: "100dvh"` and reduce ambient gradient opacity so the embedded canvas remains the focal point.
  - _Suggested command_: `$impeccable adapt packages/ui`

### Persona Red Flags

- **Alex (Power User)**: Keyboard navigation works cleanly inside `Segmented` and `RadioGroup`, but the toolkit provides zero global keyboard shortcut primitives or hotkey annotations on `Button` / `ControlPanel`, slowing down high-speed power users.
- **Sam (Accessibility-Dependent)**: `ControlSection` headers are invisible to screen reader heading navigation (`H` key) because they are implemented with `<span>` rather than `<h3>`. In addition, scrubbing a `ColorField` triggers an announcement storm due to unthrottled `aria-live="polite"` on the value readout.
- **Riley (Deliberate Stress Tester)**: Passing a `family` prop to `Button` creates unspaced visual clumping between the LED dot and button text due to missing `gap`. Docking `ExperimentShell` renders blurred translucent glass over solid page backgrounds, breaking contrast guarantees.

### Minor Observations

- In `RadioGroup.tsx`, `disabledStyle.base` is applied to the group container, but child `<button>` elements retain `cursor: interaction.cursorPointer` from `interactiveBase.base`, creating conflicting cursor feedback when hovering over disabled radio items.
- In `Card.tsx`, the `variant="sunken"` defines a dark recessed well, but does not provide the same subtle inset shadow (`shadows.sunken`) as `Slider.tsx`'s recessed track.
- In `Select.tsx`, standard native `<select>` styling is very clean, but options cannot display LED indicators corresponding to option families.

### Questions to Consider

- Should `ExperimentShell` completely disable backdrop blur when docked, or should docking use a distinct opaque matte token (`panel-surface`)?
- Should `packages/ui` introduce a lightweight `Tooltip` or `HelperText` primitive to satisfy Heuristic 10 (Help and Documentation) without bloating the library?
- Would migrating `ColorField` from raw HEX to OKLCH/Hue-Chroma sliders better fit the creative coding instrument ethos of the toolkit?
